# เปิดเว็บที่สองด้วยโค้ดชุดเดิม

ใช้ได้กับกรณีอย่าง "บ้านเรา" กับ "กลุ่มแฟน" — คนละกลุ่ม คนละข้อมูล คนละหน้าตา
แต่ใช้โค้ดชุดเดียวกัน แก้บั๊กทีเดียวได้ทั้งสองเว็บ

```
GitHub repo เดียว
      │
      ├── Vercel project "home-ledger"   → Supabase project A   (บ้านเรา, ฿, ฟ้า-ขาว)
      └── Vercel project "mates-ledger"  → Supabase project B   (กลุ่มแฟน, A$, พาสเทล)
```

**ห้ามใช้โปรเจกต์ Supabase เดียวกันสองกลุ่ม** เพราะฟังก์ชัน `enter_family` ออกแบบมา
ให้ฐานข้อมูลหนึ่งชุดมีบ้านเดียว คนของกลุ่มที่สองจะหลุดเข้าบ้านของกลุ่มแรก
แยกโปรเจกต์ยังได้โควตาฟรีของตัวเองอีกชุดด้วย

---

## ขั้นที่ 1 — สร้างโปรเจกต์ Supabase ใหม่

ทำเหมือน [SETUP.md](SETUP.md) ขั้นที่ 1–3 ทุกอย่าง แต่ตั้งชื่อโปรเจกต์ใหม่ เช่น `mates-ledger`

- Region: **Southeast Asia (Singapore)** ถ้าคนส่วนใหญ่อยู่ไทย
  หรือ **Australia (Sydney)** ถ้าทั้งกลุ่มอยู่ออสเตรเลีย — เลือกที่ใกล้คนใช้จริง
- SQL Editor → รัน `supabase/schema.sql` ทั้งไฟล์
- แล้วรัน `supabase/migrations/005_receipts.sql` เพื่อเปิดใช้รูปใบเสร็จ
  (ไฟล์ 001–004 ไม่ต้องรัน เพราะ `schema.sql` รุ่นปัจจุบันรวมไว้ให้แล้ว)
- Authentication → Sign In / Providers → Email → **ปิด Confirm email**

## ขั้นที่ 2 — สร้าง Vercel project ที่สอง

vercel.com → **Add New… → Project** → เลือก repo เดิม → **Import**

ตั้งค่าเหมือนเดิมทุกอย่าง (**Root Directory = `home-ledger/web`**) แต่ Environment
Variables ใส่ชุดใหม่:

| Name | Value |
|---|---|
| `VITE_SUPABASE_URL` | URL ของโปรเจกต์ **ที่สอง** |
| `VITE_SUPABASE_ANON_KEY` | คีย์ของโปรเจกต์ **ที่สอง** |
| `VITE_APP_NAME` | `บัญชีกลุ่มเรา` |
| `VITE_THEME` | `pastel` |
| `VITE_CURRENCY` | `AUD` |
| `VITE_LOCALE` | `en-AU` |
| `VITE_YEAR_FORMAT` | `ce` |
| `VITE_HOUSEHOLD_SLUG` | `mates` ← **ต้องไม่ซ้ำกับเว็บแรก** |
| `VITE_PEOPLE` | `01:ชื่อคนที่1,02:ชื่อคนที่2,03:ชื่อคนที่3,04:ชื่อคนที่4` |
| `VITE_SPLIT` | `on` ← เปิดฟีเจอร์หารเท่า |

กด Deploy แล้วตั้ง **Settings → Git → Production Branch** ให้ตรงกับ branch ที่ใช้จริง

> `VITE_HOUSEHOLD_SLUG` สำคัญมาก มันคือสิ่งที่แยกบัญชีล็อกอินของสองเว็บออกจากกัน
> ถ้าตั้งซ้ำ รหัส `01` ของสองกลุ่มจะพยายามใช้บัญชีเดียวกัน

## ขั้นที่ 3 — เข้าใช้งาน

คนแรกในกลุ่มพิมพ์รหัสตัวเอง → ระบบสร้างบ้านใหม่ให้อัตโนมัติ
คนที่เหลือพิมพ์รหัสของตัวเอง → เข้าบ้านเดียวกันเอง ไม่ต้องใช้รหัสเชิญ

## รูปใบเสร็จทำงานยังไง

- แตะ **📷 ถ่ายรูป หรือเลือกจากคลัง** ในหน้าบันทึกรายการ บนมือถือจะเปิดกล้องให้เลย
- แอป**ย่อรูปในเครื่องก่อนอัปโหลด** ให้ด้านยาวสุดไม่เกิน 1600px แปลงเป็น JPEG
  รูปจากกล้อง 3–5 MB จะเหลือราว 150 KB — โควตาฟรี 1 GB เก็บได้เป็นหมื่นใบ
- ไฟล์เก็บใน Storage ถัง `receipts` แบบ **ไม่เปิดสาธารณะ** เปิดดูได้ผ่านลิงก์ชั่วคราว
  อายุ 1 ชั่วโมงที่แอปขอให้เท่านั้น
- ชื่อไฟล์เป็น `<รหัสบ้าน>/<รหัสคน>/<สุ่ม>.jpg` กติกาฝั่งฐานข้อมูลจึงบังคับได้ว่า
  **คนในกลุ่มดูใบเสร็จได้ทุกใบ แต่ลบหรือเปลี่ยนได้เฉพาะใบที่ตัวเองอัปโหลด**
- รายการที่มีใบเสร็จจะมีไอคอน 🧾 นำหน้าในหน้ารายการ
- ต้องออนไลน์ตอนแนบรูป ถ้าเน็ตหลุดให้บันทึกรายการไปก่อนแล้วกลับมาแนบทีหลังได้
- ถ้าไม่อยากใช้ฟีเจอร์นี้ ตั้ง `VITE_RECEIPTS=off` ปุ่มจะหายไป

## เว็บบ้านเราที่ใช้อยู่แล้ว

ปุ่มแนบใบเสร็จจะโผล่ขึ้นมาด้วย ถ้าอยากใช้ให้รัน `supabase/migrations/005_receipts.sql`
ในโปรเจกต์ Supabase ของบ้านเรา ถ้ายังไม่อยากใช้ก็ตั้ง `VITE_RECEIPTS=off` ไว้ก่อน
(ถ้าไม่ทำอะไรเลย ปุ่มจะยังอยู่ และจะขึ้นข้อความบอกให้รันไฟล์นี้เมื่อกดใช้)

## หารเท่า

เปิดด้วย `VITE_SPLIT=on` และต้องมีตาราง `expense_shares` ในฐานข้อมูล
(โปรเจกต์ที่สร้างใหม่จาก `schema.sql` รุ่นปัจจุบันมีให้แล้ว ส่วนโปรเจกต์เดิม
ให้รัน `supabase/migrations/006_split_expenses.sql`)

### ใช้ยังไง

1. บันทึก **รายจ่าย** ตามปกติ — คนที่บันทึกคือคนที่ออกเงินไปก่อน
2. ติ๊ก **หารเท่า** แล้วเลือกชื่อเพื่อนที่จะช่วยหาร
3. แอปคำนวณให้ทันที เช่น 20 เหรียญ หาร 3 คน → คนละ 6.67 ส่วนของคนออกเงิน 6.66
   (เศษสตางค์ตกที่คนออกเงิน เพราะเป็นคนเลือกหารเอง)
4. เพื่อนที่ถูกเลือกจะเห็นยอดของตัวเองในแท็บ **🤝 หารกัน**
5. พอจ่ายเงินคืนกันแล้ว **คนที่ติดหนี้กดติ๊ก** ในช่องได้เอง ทุกคนเห็นพร้อมกัน

### กติกาที่บังคับในฐานข้อมูล

| ใคร | ทำอะไรได้ |
|---|---|
| ทุกคนในกลุ่ม | เห็นว่าใครติดใครเท่าไหร่ |
| คนออกเงิน | สร้าง แก้ยอด ลบส่วนแบ่ง และติ๊กแทนได้ |
| คนที่ติดหนี้ | ติ๊กว่าจ่ายคืนแล้วได้เท่านั้น — แก้ยอดตัวเองไม่ได้ ลบทิ้งไม่ได้ ติ๊กแทนคนอื่นไม่ได้ |

ลบรายการจ่ายต้นทาง ส่วนแบ่งทั้งหมดของรายการนั้นหายตามอัตโนมัติ

### รายงาน "ใครใช้เท่าไหร่" มีสองมุม

- **จ่ายจริง** — ใครควักเงินออกไปเท่าไหร่ (ใครบังเอิญเป็นคนจ่ายบิล)
- **หลังหารแล้ว** — ใครกินใครใช้จริง ๆ เท่าไหร่ หลังหักส่วนที่เพื่อนต้องคืน

เช่น ฝ้ายจ่ายค่าแท็กซี่ 45 แล้วหาร 3 คน — ฝั่ง "จ่ายจริง" ฝ้ายขึ้น 45
แต่ฝั่ง "หลังหารแล้ว" ฝ้ายเหลือ 15 ส่วนอีก 30 ไปอยู่กับอีกสองคน
